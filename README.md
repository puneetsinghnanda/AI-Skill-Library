# Truminds AI Skill Library

SDLC skills, workflows and a quality harness that run locally in Claude Code (desktop app, company seats) through the `truminds` plugin. No Claude API calls. Approver: Puneet Singh Nanda.

This repository is the **source of truth** for every design document and all code. Change anything by pull request.

## Layout

Every top-level folder in the repository:

```text
.claude-plugin/       marketplace.json, marketplace "truminds-skill-library" (SDD-05 §3.3)
.devcontainer/        dev container with the tools `make test-all` needs (DEV-01 §3; draft)
.github/              CI workflows, CODEOWNERS, PR and issue templates (GOV-01, OPS-03)
deploy/               single-VM deployment: Compose, edge, backups, systemd (OPS-01)
docs/                 all documents; start at docs/README.md
examples/             sample-system/: React + Node.js + PostgreSQL brownfield sample, invented data (TST-01 §4)
harness-evals/        harness-accuracy labelled set scored by `tsl harness eval` (SDD-03 §16; starter set)
managed-settings/     managed-settings template for the Claude org admin (SDD-05 §6)
ops/                  monitoring as code: alerts, recording rules, dashboards, probes (OPS-02)
plugins/              truminds/: the plugin: skills, agents, hooks, workflows, policy (SDD-01, SDD-05)
pods/                 Release-1 pod definitions, pod.v1 (SDD-10)
portal/               React intranet portal (SDD-09)
schemas/              JSON Schemas for every contract, with valid and invalid fixtures (Doc 5 §3)
scripts/              repo checks: links, registry ids, doc control rows, commit messages, backlog.csv
services/             insights/: FastAPI insights service + PostgreSQL 16 (SDD-08)
spikes/               spike plugin and runbooks for unverified platform facts (SDD-05 §8)
tsl/                  truminds-tsl, the Python 3.12 command-line tool (SDD-04)
```

`.pytest_cache/`, `.ruff_cache/`, `node_modules/` and `.venv/` folders are generated by local runs and never committed.

## Quick start

Prerequisites (DEV-01 §3.1): git, [uv](https://docs.astral.sh/uv/) (it fetches Python 3.12), Node 20 and 22, and PostgreSQL 16 binaries in `/usr/lib/postgresql/16/bin` or `PG_BIN`. Docker is optional for the tests. Or open the repo in the dev container (`.devcontainer/`).

```sh
make help          # list the targets
make test-all      # every component test suite, the way CI runs them
make lint-all      # linters and type checkers
make docs-check    # relative links, registry ids, doc control rows, backlog.csv in sync with PLN-01
make check-all     # all of the above plus the portal end-to-end tests
```

Single components: `make test-tsl`, `test-schemas`, `test-plugin`, `test-insights`, `test-portal`, `test-sample`, `test-deploy-ops`. Per-component setup and run commands are in [DEV-01 §3.3](docs/development/DEV-01-developer-guide.md#33-component-setup).

## Rules that apply to every change

- Never write to Jira, Confluence or a client system without explicit approval.
- No client names, customer data, credentials or client code in this repo, evals, fixtures or demos.
- Use company SSO (Microsoft Entra ID) libraries for all authentication; never roll custom auth.
- No back doors, debug bypasses or hidden endpoints. Encrypt data at rest.
- No secrets, credentials or API keys in code or config committed to git.
- Flag rule conflicts instead of working around them.
- Domain-agnostic: examples must not assume any one client domain.
